fix(webdav): 条件请求防覆盖 + RFC 4918/9110 合规修补

用户要求适配最新 WebDAV 标准。先澄清一个常见误解并写进文档：
RFC 4918（2007）至今是唯一的 WebDAV 基础标准，从未被废弃（webdav.org 的
规格清单里被废弃的是 RFC 2518）。所谓「更新」的是 HTTP 核心语义
（RFC 9110/2022 取代 RFC 7231）以及若干扩展（RFC 5689/5789 等）。

新增 scripts/rfc-probe.mjs 对线上实测，11 项中 7 通过 4 待改进。其中两项
不是合规洁癖而是**真实 bug**：

  If-None-Match: *  →  之前返回 204 直接覆盖
  If-Match 校验 ETag →  之前返回 204 完全不校验

同步客户端（rclone / rsync 类 / Zotero / Calibre）靠这两个头实现
「仅新建不覆盖」。服务端不校验 = 并发上传时可静默覆盖他人书籍且双方不知情。
这对「所有人可上传」的公共书库是数据安全问题，不只是协议洁癖。

本次修复：
- 新增 src/lib/preconditions.ts：RFC 9110 §13.1 If-Match/If-None-Match 完整
  语义，含弱比较( W/ 前缀)、多 ETag 列表、通配 *，以及资源不存在时的行为
- PUT 在**写入前**求值条件，失败返回 412 —— 顺序很关键，放到写后就失去意义
- OPTIONS 宣告 DAV: 1, 3（RFC 4918 §18）。不宣告 2，因为不支持 LOCK；
  虚报会让客户端做出错误假设
- PROPPATCH / LOCK / MOVE / COPY 改用合规的 <D:error> 体 + 预置条件元素
  （cannot-modify-protected-property、supported-lock）。此前返回纯文本，
  部分客户端解析失败会当作传输故障反复重试

同时修正我自己写测试时的两个错误：DAV 头断言值、以及用例间共享状态
（beforeEach 会重置库，条件请求测试必须各自自建文件）。

新增 12 项测试（条件请求 11 + DAV 错误体 3），90 个测试全绿。
实测确认 Range 分段下载本来就可用（206，R2 处理）。
