# 前端设计说明：开架目录

> 这份文件解释 `src/lib/theme.ts` 与四个页面里那些「看起来可以随便改」的
> 样式决定**为什么是这样**。改之前先读一遍 —— 下面每一条都是踩过一次的坑。

## 一、身份从哪来

上一版的身份建立在三根柱子上：深色底、一道琥珀光、宋体标题。三根都不成立：

1. **深色底 + 单一暖强调色**是 AI 生成深色站点的默认配方。它不表达「图书馆」，
   只表达「这是个深色主题的页面」。
2. **宋体在实际用户机器上基本不存在。** 本机 `fc-list :lang=zh` 只有
   `DroidSansFallbackFull.ttf` 一个中文字体；Linux、Android、部分 Windows
   同样没有 Songti/SimSun。所有衬线标题在真实环境里都回退成黑体，
   靠衬线建立的「书卷气」全部蒸发 —— 而在开发者自己的 Mac 上看是好的，
   所以这个缺陷特别隐蔽。
3. 五张**渐变假书脊**卡片是纯装饰：它画了一根书脊，却不告诉你里面有书没有。

这一版的身份改由**版面**承担，取材于图书馆里真实存在的三种印刷品：

| 页面 | 参照物 | 承担身份的版面特征 |
| --- | --- | --- |
| 首页 | 目录页（table of contents） | 编号 + 名称 + 说明，右列对齐成一条竖线，细线分行 |
| 目录浏览 | 卡片目录 / 排架索引 | 字母格带本数，多列索引；书是书目行不是卡片 |
| 同人在传书 / 求书墙 | 借阅登记簿 | 名字一列、数字右对齐、细线分隔、真实行号 |

这些在任何字体下都成立。**字体只负责好看，不负责表达身份。**

## 二、颜色：三种颜色，三种职责

```
--ink   #0b100e   墨绿黑，不是暖黑
--paper #efe6d4   纸
--brass #dca85f   黄铜 —— 只给交互与活态
--jade  #8fb3a4   铜绿 —— 只给结构性信息
```

**黄铜只出现在要被点的东西上**：链接、按钮、当前项、可点的数字。
它**不用**于静态装饰边框 —— 上一版全站统一 `--line: rgba(255,180,77,.5)`，
于是每张卡、每条分隔都是同一种琥珀描边，页面糊成一片「橙色描边汤」，
层级完全消失。现在：

- 结构分隔用**纸色细线** `--rule`（paper @ .14）
- 交互控件边框用**纸色实线** `--edge`（paper @ .42，3.53:1，满足 WCAG 1.4.11）
- 暖色边框 `--edge-warm`（brass @ .6，3.86:1）只用在 hover / 激活态

一页里黄铜出现在三处以内，它才有意义。

底色从暖黑（`#0e0c0a`）换成偏冷的墨绿黑（`#0b100e`），是因为暖黑 + 橙
就是那个「AI 默认深色站」的标准配方；偏冷的墨配黄铜，是旧图书馆里
黄铜灯罩与氧化铜配件的关系。

## 三、版面规则（可复用）

- **右对齐的数字列**。本数、页数、大小、字数一律 `font-variant-numeric:
  tabular-nums` 并右对齐成一列。这是目录页/登记簿最重要的视觉特征，
  也是唯一一个「有信息密度却不吵」的手法。
- **细线分行，不用卡片框**。目录页用 `border-bottom: 1px solid var(--rule)`
  分行；一组数据用一个 `.dirs` / `.roll-list` 容器的最后一条底线收口。
  卡片边框（尤其是全站同强度的）会把所有内容压平成同一种东西。
- **行号是真的**。`01 02 03` 是列表的序号（`counter` 或索引），不是装饰。
- **空状态说清下一步**，不只是「暂无数据」。

## 四、踩过的坑（别再踩）

### `var()` 拼错不会报错，只会静默失效

上一版 `src/home-page.ts` 写了 `var(--ink2)`（主题里叫 `--ink-2`）。
一个连字符之差，整条 `background` 声明在计算值时失效，首页五张书架卡
**完全没有背景**，在深色页上看起来像「透明的卡片」—— 而且不报任何错。
现在改用 `--ink-2` 的地方都有截图核对。

### `<span>` 在 `flex-direction: column` 父元素里会被拉满整行

浏览页的上传者署名 `.ccredit` 是 `display:inline-block` 的 `<span>`，
但父元素是 `display:flex; flex-direction:column`，默认 `align-items: stretch`，
于是它被拉成整行宽，再加上 `border-left` 和淡琥珀底 ——
**看起来像一根进度条**。column flex 里任何「应该只有内容那么宽」的元素
都要显式 `align-self: flex-start`。

### `repeat(auto-fill, ...)` 在条目少时会留空轨道

`auto-fill` 会填满整行轨道数，条目不够就留空轨道，内容挤在左半边。
只有 2 个条目时（「按类型」就是漫画 + 电子书）尤其明显。
**条目数量可变的网格用 `auto-fit`。**

### 移动端不要藏掉「大小」

`.csize{display:none}` 曾经在手机上藏掉文件大小。但 `48.8 MB` 正是
「点不点开」的判断依据，而它只占约 50px。藏掉的应该是装饰，
不是决定要不要点的那条信息。

### 同一句话不要写两遍

- 首页最近上架卡：作者和上传者是同一个人时曾渲染成「刘慈欣 · 刘慈欣 传来」。
- 浏览页书卡：署名与作者同名时重复。
- 目录页：每个字母格右边都写「目录」—— 同一个词重复 13 次，
  而那一列本该写本数。

## 五、可访问性基线（`scripts/contrast-check.mjs` 可复核）

```
node scripts/contrast-check.mjs    # 不达标时退出码 1
```

- 正文 `--paper` / `--ink`：**15.47:1**
- 次要 `--paper-dim`：**7.53:1**
- 链接 `--brass`：**8.96:1**
- 交互边框 `--edge`：**3.53:1**（非文字，需 3:1）
- 暖边框 `--edge-warm`：**3.86:1**

其他基线：

- 所有点击目标（含页脚链接、面包屑、返回链接）`min-height: 44px`
- `:focus-visible` 全站统一 2px 黄铜描边
- `prefers-reduced-motion: reduce` 关掉呼吸光、闪烁点与淡入
- 输入框 `::placeholder` 统一 `--paper-dim`（浏览器默认 #757575 在深底上不够）

⚠️ **`contrast-check.mjs` 的色值是手抄的**，不自动读 `theme.ts`。
改配色必须同步改它 —— 否则它会在旧色板上全部「达标」，一次都不会红。
（上一版换色后就发生了这件事。）

## 六、受测试保护的形状（改之前先看测试）

以下字符串被 `test/` 下的断言或 `scripts/verify-deploy.mjs` 锁死：

- `class="card bookcard" href="..."` / `class="card shelfcard" href="..."`
  （属性顺序也不能变）
- 首页 `<div class="fresh" id="fresh" hidden>`、`renderFresh(d.latest)`、
  `title.href = latest.downloadUrl || latest.href`、全文仅一次
  `fetch('/api/credits'`
- `.roll-list li.collective{...grid-column:1/-1}` 与 `.roll-list li.personal`
- 上传页 `#credit` 必须在 `#drop` **外面**（在里面会导致点输入框弹文件框）
- 每页 `.wrap{` 只定义一次，且 `max-width` 五个页面一致（现在 64rem）
- 全文不得出现字面 `${`（模板串会在构建时被插值）

## 七、预算约束对设计的硬限制

免费层十万次请求/天，因此：

- **不引外部字体/CSS/图片**（CSP `default-src 'none'` 也不允许）。
  身份必须靠系统字体 + 版面。
- 书卡直链 R2 公开域，点一本书不经过 Worker（省一次请求 + 一次 302）。
- 首屏「最近上架」由 `/api/credits` 一次 fetch 填充，首页 HTML 本身不查 D1。
- 目录页的本数来自 `buckets` 表（`listBucketTotals` 本来就查了），
  **不额外多查一次 D1** —— `childCount` 只是把已有结果带到渲染层。
